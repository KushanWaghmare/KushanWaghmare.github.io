## 2. Identification & Removal of Earlier Standalone Particle Code

### What Was Wrong in the Previous Attempt
1. **Duplicate / Competing Particle Systems & Canvas Crossfading**:
   - `build-static.js` and `shared/app.js` created a `<canvas>` element inside every `.snap-section .sim-stage`, and `shared/app.js` mounted independent per-section simulations (`gpu-hub.js`, `gpu-cy.js`, `blackhole.js`, `gpu-diffusion.js`, `gpu-crystal.js`, `gpu-qsim.js`, `engines.js`) onto those canvases.
   - `shared/gfx.js` created an offscreen WebGL2 canvas (`document.createElement("canvas")`) and blitted pixels to 2D canvases via `ctx2d.drawImage`.
   - `shared/gpu/gpu-thread.js` added a separate `#stage-canvas` that rendered static placeholder shapes (`shared/gpu/gpu-thread-formations.js`) during scroll and crossfaded against the section canvases using CSS `--native-opacity` (`shared/style.css` lines 399–413).
2. **Placeholder Formations Instead of Real Simulations**:
   - `shared/gpu/gpu-thread-formations.js` did not run the real simulations: it used a static 4D hypercube for Computer Science instead of the Grover/Shor quantum simulator, static concentric circles for Quant instead of the binomial option-pricing crystal, a static logarithmic spiral for Data Science instead of the reverse-time Gaussian-mixture score SDE, and Euler steps for Lorenz.

### Removal & Consolidation Actions
1. **Remove Per-Section `<canvas>` Elements**:
   - Remove `<canvas aria-hidden="true"></canvas>` from all `.snap-section .sim-stage` templates in `build-static.js` and `shared/app.js`. Only `#stage-canvas` exists as the single full-viewport WebGL stage canvas in the DOM.
2. **Remove Crossfade CSS (`--native-opacity`)**:
   - Delete `--native-opacity` rules in `shared/style.css` and `shared/gpu/gpu-thread.js`. Zero crossfading of canvases occurs at any frame.
3. **Fold Existing Simulation Maths into `Formation` Adapters on the Single Shared Buffer**:
   - Replace `shared/gpu/gpu-thread-formations.js`, `shared/gpu/gpu-thread-shaders.js`, and `shared/gpu/gpu-thread.js` with the unified single-buffer `THREE.Points` stage and per-section `Formation` adapters driven directly by `CYMath`, `BLACKHOLE_PHYSICS` + `BLACKHOLE_SHADERS`, `DiffusionMath`, `LatticeMath`, `QSimMath`, and `ENGINES`.
